## Цель

Инструкция для команд-потребителей: как сделать данные сервиса доступными всем пользователям одной группы (и только им), используя клеймы `groups` / `organization` / `scope`.

## Что сделать

Написать `docs/integrations/group-data.md`:

1. Чтение клеймов в сервисе: `groups`, `organization`, `scope` — где взять, как распарсить (`scope` — строка через пробел).
2. Паттерн «данные доступны всем пользователям группы»:
   - схема расширения БД сервиса (например, таблица связки `resource ↔ group` / колонка `group_name`);
   - пример фильтра запроса: `WHERE group_name = ANY(@userGroups)` или эквивалент на EF Core;
   - авторизация endpoint по группе (пример кода из demo-api `/group-data`).
3. Вариант с организацией: когда фильтровать по `organization` вместо/вместе с группами.
4. Ограничения: группы уникальны внутри организации (именование/конфликты), что делать при переименовании группы.
5. Проверка: сценарий на demo-api — два пользователя одной группы видят групповой ресурс; пользователи другой группы или организации — 403.
6. Зафиксировать изменение в `docs/CHANGELOG.md`.
