# Task 07: src/portal — ASP.NET 10 портал администратора (P4)

- **Статус:** open
- **Фаза:** PRD P4
- **Зависимости:** task-02 (realm, клиент `portal`, организации, пользователи)
- **Источник:** план §5.7, §6; PRD FR 6, milestone P4

## Цель

Портал администратора: CRUD пользователей и групп своей организации, назначение ролей и сервисов, функции суперадмина. Поверх Keycloak Admin REST API, org-изоляция — в логике портала.

## Что сделать

`src/portal/` — ASP.NET Core **.NET 10**:

1. **Аутентификация**:
   - OIDC-логин администратора через Keycloak (конфиденциальный клиент `portal`);
   - сервис-аккаунт портала для вызовов Keycloak Admin REST API (секрет из `.env`).
2. **API (минимум)**:
   - CRUD пользователей своей организации: создание (email), назначение групп/ролей/атрибута `services`;
   - валидация `services ⊆ availableServices` организации пользователя (список сервисов — фиксированные константы портала: `cryptoservice`, `cadastralservice`, `cadastralanalyticservice`);
   - CRUD групп своей организации;
   - смена/сброс пароля пользователя (set-password / required action `UPDATE_PASSWORD`);
   - суперадмин: CRUD организаций, управление атрибутом `availableServices` организации.
3. **Org-изоляция** — единственное место инварианта «admin видит только свою организацию»:
   - admin организации A при запросе пользователей/групп организации B → 403/404;
   - покрыть тестами (task-08).
4. **Запреты** (по PRD):
   - создание realm-ролей через портал невозможно (роли только `user`/`admin`/`auditor`);
   - создание элементов scope невозможно (список фиксирован константами).
5. **Минимальный Web UI**: список пользователей/групп, формы создания (Razor Pages или минимальный JS — на усмотрение исполнителя).
6. Зафиксировать изменение в `docs/CHANGELOG.md`.

## Критерии готовности (из плана §7, P4)

- [ ] Через API портала создан пользователь в org A (email, роль, группа, services)
- [ ] admin org A получает 403 при доступе к пользователям org B
- [ ] Суперадмин создаёт организацию и меняет её `availableServices`
- [ ] Назначение пользователю сервиса вне `availableServices` организации → 400
- [ ] Web UI показывает пользователей/группы и позволяет создать пользователя
- [ ] Запись в `docs/CHANGELOG.md`
