## 2. Problem Statement

В нашей компании есть много сервисов, которые предоставляют чувствительные данные. Необходимо создать механизм предоставления доступа только для авторизованных пользователей.
В нашей компании есть много клиентов из разных компаний, мы должны разделять их зоны видимости.
Для пользователя мы должны предоставить механизмы:

- аутентификации (для web ui и api)
- авторизации (для web ui и api)
- самообслуживание для сброса и смены пароля.

### безопасность

Должна быть защита от перебора паролей пользователя.
В ответе на ошибку аутентификации нельзя явно сообщать существует ли такой username

### расширения для пользователя

У пользователей должна быть одна организация. Организация ограничивает доступные группы, пользователей и видимость администратора и пользователей.

У пользователей должны быть группы. некоторые продукты используют группы для предоставляния данных на основе групп.
Пользователь может принадлежать нескольким группам одновременно.

У пользователя должны быть роли: `user`,`admin`,`auditor`. На основе этих ролей пользователь будет предоставлять различные права работы.

У пользователя должен быть доступный `scope` для обозначения доступных сервисов

## 6. Functional Requirements

1. Использовать keycloak как identity provider
2. Расширить схему данных о пользователе в keycloak
3. Реализовать корректное формирование jwt c полным набором данных
4. реализовать инструкцию для dotnet core 10 asp.net по настройками authenticate механизма для корректной работы [Authorize],[Authorize(Role)]
5. Реализовать инструкцию по расширению схемы данных сервисов для возможности работать с группами (данные должны быть доступны для всех пользователей группы)
6. Реализовать портал администратора для отображения всех пользователей, групп, ролей и Scopе для управления пользователями организации. Администратор может управлять только пользователям и группами своей организации.
    - администратор может делать CRUD пользователей внутри своей организации
    - администратор может назначать пользователям группы
    - администратор может назначать пользователям роли и сервисы из scope
    - администратор может делать CRUD групп внутри своей организации
    - администратор не может создавать новые роли. Роли зафиксированы: `user`,`admin`,`auditor`
    - администратор не может создавать элементы scope. Scope может задавать суперадминистратор. Scope задается для каждой организации. Базовый scope = [cryptoservice,cadastralservice,cadastralanalyticservice]
